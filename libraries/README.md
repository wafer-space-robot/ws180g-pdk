# libraries/: the library repositories

Each library of the PDK has a repository of its own, held here as a git submodule. A
library repository holds generated output only, one file per item: its content is
generated by the build of this meta-repository and committed by that build. Nothing in a
library repository is edited by hand; change the process description or the generators here
instead. The decision and its reasons are in section 8.1 of the
[design document](../docs/superpowers/specs/2026-10-26-ws180g-pdk-design.md).

| Submodule | Repository | Content |
|-----------|------------|---------|
| `ws180g005_fd_pr` | <https://github.com/wafer-space-robot/ws180g005_fd_pr> | primitives |
| `ws180g005_fd_io` | <https://github.com/wafer-space-robot/ws180g005_fd_io> | 5 V IO |

In Phase 0 both are placeholders: a README and the licence, no library content.

## The standard-cell library comes in Phase 1

The general-purpose 5 V standard-cell library is named `ws180g005_fd_sc_gp<N>t5v0`, where
`N` is the track count the cell generator settles on. The repository's name contains `N`, so
it is created in Phase 1, once the track count exists, and added here as a third submodule.

## Working with the submodules

A plain `git clone` leaves each submodule as an empty directory, which is all that the tests
and the Phase 0 build need. To fetch their content:

```
git submodule update --init
```

The submodule URLs are HTTPS, so reading them needs no GitHub account.

`uv run ws180g-check-names` checks every directory here against the library naming rules
(and, once there is content, the cell and corner names inside it).

## Repository settings

The library repositories carry the same settings as this repository (merge commits only,
protected `main`, the version-tag ruleset). The settings are the JSON files in
[`tools/repo-settings/`](../tools/repo-settings/), and `apply.py` there creates a library
repository from them and from the library's seed directory:

```
uv run tools/repo-settings/apply.py wafer-space-robot/ws180g005_fd_pr \
    --seed tools/repo-settings/seed/ws180g005_fd_pr
uv run tools/repo-settings/apply.py wafer-space-robot/ws180g005_fd_io \
    --seed tools/repo-settings/seed/ws180g005_fd_io
```

In a seed directory, `files/` is the content of the first commit (the library's README; the
script adds this repository's `LICENSE`), which has to exist before `main` is protected,
`commit-message.txt` is that commit's message and `description.txt` the repository
description. Add `--dry-run` to print the commands without running any.

Both repositories were created on 2026-11-10 with these two commands and, in addition, two
options the script had at the time, which gave the commit message and the description on
the command line. That message and those descriptions are the ones now committed in the seed
directories, so the commands above reproduce the same content, message, description and
settings.

`uv run tools/repo-settings/verify.py <owner/repo> --seed <seed directory>` compares a
repository's live settings and description with the files and changes nothing.
